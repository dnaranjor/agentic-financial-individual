## 1. Two Lineages (TAD-01)

The brief's single chain is **revised, not preserved**. Assumptions never harden into facts; facts never soften into assumptions. Analysis consumes both and records which is which (`TARGET-ARCHITECTURE.md:236-252`).

**Lineage 1 — Household reality (backward-looking):**

```
EVIDENCE ──extraction──▶ OBSERVATION ──synthesis/attestation──▶ CLAIM ──acceptance──▶ ACCEPTED FACT
                                                                                           │
                                                                               (derivation, never assertion)
                                                                                           ▼
                                                                                   FINANCIAL STATE (view)
```

**Lineage 2 — Future posits (forward-looking):**

```
ASSUMPTION ──grouping──▶ ASSUMPTION SET ──selection──▶ input to ANALYSIS
```

Meeting point only inside `ANALYSIS` (`STATE SNAPSHOT + ASSUMPTION SET + MARKET OBSERVATIONS + RULE VERSIONS → DERIVED VALUES`). Every `Analysis Record` captures source lineage per value (`TARGET-ARCHITECTURE.md:436-464`).

## 2. Epistemic Core — Identities, Lifecycles, Mutability

Derived from `TARGET-ARCHITECTURE.md:260` V.3, normative here.

| Concept | Definition | Identity | Lifecycle | Mutability | Owner |
|---------|------------|----------|-----------|------------|-------|
| **Evidence** | Immutable source artifact: document bytes, captured web content, or transcript of principal statement | Content hash `SHA-256` (preserves `shared/evidence/index.md` convention) | `acquired → retained` (retention/erasure on payload, not identity) | **Immutable** | Evidence & Observation Store (L2) |
| **Observation** | Structured reading of exactly one Evidence by specific extractor version at time: "document D states X as of T" | Own ID = `(evidence hash, extractor version, time)` | `proposed → superseded` (re-extraction creates new Observation, old remains) | Append-only | Ingestion capability proposes, L2 validates |
| **Claim** | Proposition about household/world. Sources: ≥1 Observations, principal attestation (no document), external research citation | Own ID (UUID) | `proposed → accepted \| rejected \| superseded`. **Conflicting Claims coexist**; conflict is Finding, resolution is acceptance Decision | Status only | L3 proposes, L2 validates shape |
| **Accepted Fact** | Claim accepted into household state after validation (+ human confirmation when material, e.g., >5% discrepancy intent) | Own ID + bitemporal `(valid_from, valid_to, recorded_at)` | valid-from/valid-to × recorded-at; corrections supersede via new Fact | Bitemporal append-only | Household State Service (sole writer, `B-2`) |
| **Financial State** | Derived answer "position at time T as believed at time R": accepted facts valid at T + valuations + effective rules | **Not entity — query result**; frozen snapshot ID when materialized for analysis | Recomputed at will; frozen snapshots immutable | Derived only | Calculation Engine (deterministic) |
| **Assumption** | Explicit forward-looking parameter (inflation, return, longevity, FX path) with owner, justification, optional evidence links | Own ID, versioned within Assumption Set | `authored → revised (new version) → superseded` | Versioned | Assumption Registry (principal adoption) |
| **Market Observation** | Dated, sourced external measurement (UF `39405 CLP`, FX, CPI, price) with freshness class | `(series, as-of, source)` | `observed → aged → stale` | Append-only | Market Observation Service |
| **Assumption Set** | Versioned grouping of Assumptions for one analysis | Own ID + version | Immutable version | Immutable per version | Assumption Registry |
| **Derived Value** | Output of deterministic computation: `{value, unit, basis, formula ID, input refs (snapshot+assumptionSet+ruleVersions), engine version}` | Own ID within Analysis Record | Computed once per run | Immutable | Calculation Engine only |
| **Finding** | Detected risk/inconsistency/staleness/conflict with severity + triggering refs | Own ID | `raised → acknowledged \| resolved \| accepted-risk` | Status only | Risk & Consistency Gate |
| **Recommendation** | Proposed course: rationale, alternatives, Derived Values only, falsification conditions, expiry | Own ID | `draft → presented → accepted \| rejected \| deferred \| expired \| invalidated` | Immutable content; status only | Recommendation capability (gated by Risk) |
| **Decision** | Principal's recorded disposition of Recommendation | Own ID | `recorded once` | Immutable | Principal (human) only |
| **Outcome** | Later measurement of what actually happened, bound to Decision | Own ID | `observed` append-only | Immutable | Monitoring |

## 3. Transformation Boundaries — Who May Cross Each Arrow

| Transformation | Nature | Performed by | Guard |
|---------------|--------|--------------|-------|
| `Evidence → Observation` | Interpretive (extraction) | Ingestion capability (L3) proposes; Schema Registry (L2) admits per `docs/ontology/v1.md` shape | `B-5` external→Evidence only |
| `Observation/attestation/citation → Claim` | Interpretive (synthesis) | L3 proposes; L2 validates shape + source links | Confidence required |
| `Claim → Accepted Fact` | **Judgment** | Household State Service applies acceptance rules; **human confirmation required when material** (5% threshold intent preserved) | `B-2` sole writer |
| `Accepted Facts → Financial State` | Deterministic | Calculation Engine only | `B-3` no LLM inside L2 |
| `Facts + Assumptions → Derived Values` | Deterministic | Calculation Engine only | `INV-08` lineage separation |
| `Derived Values + Findings → Recommendation` | Analytical + linguistic | Recommendation Support (L3), gated by Risk (L2) `GATE-005` | `B-7` refs DerivedValue IDs only |
| `Recommendation → Decision` | Human | Principal only | Immutable after |

**No inferential arrow writes state.** `[I]`/`[G]` terminate in proposals; only `[A/H]` acceptance and `[D]` derivation touch stores (`TARGET-ARCHITECTURE.md:458-464`).

## 4. Why These Distinctions and Not Fewer — Semantic Overlap Analysis (V.4)

* **Observation ≠ Claim.** Observation is document-bound mechanical ("this PDF says balance=X"). Claim is household-level proposition resting on several observations, none (attestation), or research. Merging forces attestations to fake a document or extractions to carry household semantics they lack. `shared/evidence/index.md:9-21` `citation` field is embryo of Observation (AAR F-22).
* **Claim ≠ Accepted Fact.** Gap is where conflict lives. Two contradictory Claims (bank statement vs memory) must coexist unresolved (`TARGET-ARCHITECTURE.md:732` Contradiction Test). If Claims write directly into state, conflict is silently resolved by write order — current `shared/client-profile.json` singleton last-write-wins (`C-012`).
* **Financial State is not entity.** Stored document recreates singleton dual-writer (`C-022`). It is deterministic view; freezing for analysis produces immutable `snapshotId`.
* **Assumption not on evidence chain.** Direct consequence of `F-01 VERIFIED`: evidence/assumption unrelated in repo, reports' chain placing them together was target vocabulary. Brief five-stage chain thereby revised.
* **Market Observation ≠ Assumption.** "UF is 39405 CLP today" (measurement) vs "inflation 3.5%" (posit). One file both with one owner is defect `F-14`/`C-015`: `shared/assumptions.md` impossible `3%-real/4.8%-nominal/6%-inflation` survived because no owner for posit. Separate stores, separate owners (`TARGET-ARCHITECTURE.md:289`).

## 5. Structural Core

Kept minimal, deepened only when capability demands (P8 `TARGET-ARCHITECTURE.md:170`).

* **Person** — birth date not age (repo stores ages `VERIFIED` conceptual debt), id, residence. Eligibility evaluated per person (principal `67y` Chilean, spouse `62y` Venezuelan — `shared/client-profile.json:18-39` shape preserved in fixture).
* **Household** — set of Persons + `Ownership` shares + authority.
* **Ownership** — per-person shares and authority; *sociedad conyugal* consequences `OPEN → AWP-003` (see `docs/ontology/open.md`).
* **Account / Instrument / Obligation** — introduced at M3 with depth ledger decision requires (`TAD-14` deferred). Not expanded in v1.
* **Entitlement** — conditional benefit (PGU) is never asset; eligibility per person per rule per date (`:295` adopted from `F-05` verified competence). Maps to `jurisdiction/cl/evaluate_rule`.
* **Goal** — versioned intent; repo three retirement constants are degenerate case.

**Jurisdiction concepts** (rules with effective dates, citations, ceilings) live in `jurisdiction/` vocabulary, referenced never embedded.

## 6. Measure Core (TAD-06)

* **Unit** partitions into `currency | index_unit | instrument_qty`. `UF` is `index_unit`, not `currency`. Basis: `C-019 VERIFIED` root cause. Violating `UF→CLP currency row` must be schema-rejected at `AWP-002:12.6`.
* **MeasureBasis** = `(unit, nominal|real, base period, as-of)`. Aggregation/comparison requires identical basis. Prevents `C-015`/`C-018` class structurally.
* **Provenance** = `{source refs, formula ID, input refs, assumption set, versions}` on every Derived Value.
* **Staleness + Confidence** first-class, propagated into derived values, surfaced in explanations.
* **Income typing** — `income.net_salary {value: number, unit: CURRENCY_CLP, basis: MeasureBasis, income_semantics: enum}` — see §7.

## 7. Financial Reasoning Integrity — §8 Categories Mapped

| Brief category | Target concept | Collapse prevented by |
|---------------|----------------|----------------------|
| What is known | Accepted Fact (bitemporal) | acceptance gate V.3 |
| What was observed | Observation; Market Observation | evidence-bound identity |
| What is inferred | Derived Value with provenance | deterministic-engine monopoly `P4` |
| What is claimed | Claim (incl. research citations) | status lifecycle; coexisting conflicts |
| What is assumed | Assumption / Assumption Set | separate lineage V.2 |
| What is uncertain | Confidence, Staleness, Finding | mandatory attributes |
| What is recommended | Recommendation with falsification conditions | may reference only Derived Value IDs `B-7` |

Existing conceptual model supports none except partial evidence/assumption split (`F-01`) — this doc is new architecture.
